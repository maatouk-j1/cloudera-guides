Cloudera Manager uses various databases and datastores to store information about the Cloudera Manager configuration, as well as information such as the health of the system, or task progress.

Please review [Database Requirement for Cloudera Base on premises](https://docs.cloudera.com/cdp-private-cloud-base/7.3.2/cdp-private-cloud-base-installation/topics/cdpdc-install-configure-databases.html).

This procedure highlights the installation and configuration steps with PostgreSQL. Please review Install and Configure Databases for Cloudera Base on premises for more details: [https://docs.cloudera.com/cdp-private-cloud-base/7.3.2/cdp-private-cloud-base-installation/topics/cdpdc-install-config-postgresql-for-cdp.html](https://docs.cloudera.com/cdp-private-cloud-base/7.3.2/cdp-private-cloud-base-installation/topics/cdpdc-install-config-postgresql-for-cdp.html)

<Banner type="warning">
If you already have a PostgreSQL database set up, you can skip to the section Configuring and Starting the PostgreSQL Server to verify that your PostgreSQL configurations meet the requirements for Cloudera Manager.
</Banner>

<Banner type="info">
We will be installing the external PostgreSQL DB server on the `cldr-mngr` host.
</Banner>

## 1. Install PostgreSQL

1. Login on **`cldr-mngr` server** and Install PostgreSQL as shown in the steps below.

    <Banner type="warning">
    When you restart any process in future, the configuration for each of the services is redeployed using information saved in the Cloudera Manager database. If this information is not available, your cluster cannot start or function correctly. So, you must schedule and maintain regular backups of the Cloudera Manager database to recover the cluster in the event of the loss of this database.
    </Banner>

    Install the repository RPM.

    ```transcript
    [root@cldr-mngr ~]# sudo dnf install -y https://download.postgresql.org/pub/repos/yum/reporpms/EL-9-x86_64/pgdg-redhat-repo-latest.noarch.rpm
    ```

    Disable the built-in PostgreSQL module.

    ```transcript
    [root@cldr-mngr ~]# sudo dnf -qy module disable postgresql
    ```

    Install PostgreSQL.

    ```transcript
    [root@cldr-mngr ~]# sudo dnf install -y postgresql17 postgresql17-server postgresql17-libs
    ```

2. Install the PostgreSQL JDBC driver by running the following command on ansible-controller/ipaserver node. Rename the Postgres JDBC driver `.jar` file to `postgresql-connector-java.jar` and copy it to the `/usr/share/java` directory. The following copy command can be used if the Postgres JDBC driver `.jar` file is installed from the OS repositories: *(Skip this, as we already performed it in prior steps)*

    Install the JDBC connector.

    ```transcript
    [root@jump ~]# wget https://jdbc.postgresql.org/download/postgresql-42.7.13.jar

    [root@ipaserver ~]# mv -v postgresql-42.7.13.jar postgresql-connector-java.jar
    ```

    ```transcript
    [root@jump ~]# ansible all -m copy -a "src=postgresql-connector-java.jar dest=/usr/share/java/postgresql-connector-java.jar"

    [root@jump ~]# ansible all -m shell -a "sudo chmod 644 /usr/share/java/postgresql-connector-java.jar"

    [root@jump ~]# ansible all -m shell -a "sudo ls -l /usr/share/java/postgresql*.jar"
    ipaserver.cldrsetup.local | CHANGED | rc=0 >>
    -rw-r--r-- 1 root root 1089312 Jun 3 08:06 /usr/share/java/postgresql-connector-java.jar
    ```

    An alternate way, which is not recommended:

    ```transcript
    [root@jump ~]# ansible all -m shell -a "sudo dnf install postgresql-jdbc -y"
    [root@jump ~]# ansible all -m shell -a "java -version"
    ```

3. Make sure that the data directory, which by default is `/var/lib/pgsql/17/data/`, is on a partition that has sufficient free space.

    <Banner type="warning">
    Cloudera Manager supports the use of a custom schema name for the Cloudera Manager Server database. By default, PostgreSQL only accepts connections on the loopback interface. You must reconfigure PostgreSQL to accept connections from external hosts.
    </Banner>

4. Installing the psycopg2 Python package for PostgreSQL-backed Hue. *(Skip this, as we already performed it in prior steps)*

    <Banner type="warning">
    If you are installing Runtime 7 and using PostgreSQL as a backend database for Hue, then you must install the 2.9.3 version (or greater) of the psycopg2 package on all Hue hosts. The psycopg2 package is automatically installed as a dependency of Cloudera Manager Agent, but the version installed is often lower than 2.9.3
    </Banner>

5. Make sure the psycopg2 package dependencies for RHEL 9 is installed on all required hosts, by running the following commands:

    ```transcript
    [root@jump ~]# ansible all -m shell -a "pip3 install psycopg2-binary && pip3 list | grep psyc"

    ipaserver.cldrsetup.local | CHANGED | rc=0 >>
    Requirement already satisfied: psycopg2-binary in /usr/local/lib64/python3.9/site-packages (2.9.12)
    psycopg2-binary      2.9.12
    WARNING: Running pip as the 'root' user can result in broken permissions and conflicting behaviour with
    the system package manager. It is recommended to use a virtual environment instead:
    https://pip.pypa.io/warnings/venv
    ```

## 2. Initialize and configure the database

1. Initialize the database:

    ```transcript
    [root@cldr-mngr ~]# sudo /usr/pgsql-17/bin/postgresql-17-setup initdb
    ```

    Verify the PostgreSQL version:

    ```transcript
    [root@cldr-mngr ~]# cat /var/lib/pgsql/17/data/PG_VERSION
    17
    ```

    Verify the psycopg version:

    ```transcript
    [root@cldr-mngr ~]# pip3 list |grep psycopg
    psycopg2-binary       2.9.12
    ```

    The data directory is very critical. If you want to clean up PostgreSQL, simply rename or remove the `/var/lib/pgsql/17/data` directory.

2. Make sure that `LC_ALL` is set to `C.UTF-8` to enable UTF-8 CHARSET and initialize the database as follows:

    ```transcript
    [root@cldr-mngr ~]# echo 'LC_ALL="C.UTF-8"' >> /etc/locale.conf
    ```

3. To enable MD5 authentication, edit `/var/lib/pgsql/17/data/pg_hba.conf` by adding the following lines, to enable connection from all outside hosts:

    *(Enable md5 auth to serve password authentication and TLS/SSL encryption from outside world)*

    In the entries already in the file, replace `127.0.0.1` with the host IP if PostgreSQL has to be reachable from a different host.

    ```transcript
    [root@cldr-mngr ~]# vi /var/lib/pgsql/17/data/pg_hba.conf

    host    all              all             0.0.0.0/0              md5 # Enable md5 authentication
    host    ranger           rangeradmin     0.0.0.0/0              md5 # Allow ranger database connection from any host
    hostssl all              all             0.0.0.0/0              md5 # Allow SSL connection from client(s)
    ```

    <Banner type="info">
    The section for replication privilege needs the same edit. HA is not documented in this solution.
    </Banner>

    Back up the config so you can use it in case of a re-setup.

    ```transcript
    [root@cldr-mngr ~]# cp /var/lib/pgsql/17/data/pg_hba.conf ~
    ```

    If you have the file backed up already, copy it *(only applicable in case of resetup)*.

    ```transcript
    [root@cldr-mngr ~]# cp /var/lib/pgsql/17/data/pg_hba.conf /var/lib/pgsql/17/data/pg_hba.conf_orig
    [root@cldr-mngr ~]# cp ~/pg_hba.conf /var/lib/pgsql/17/data/pg_hba.conf
    ```

4. Configure settings to ensure your system performs as expected. Update these settings in the `/var/lib/pgsql/17/data/postgresql.conf` file. Settings may vary based on cluster size and resources. The script below declares each value as a variable, takes a timestamped backup of the file, applies the values with `sed`, then prints them back for verification:

    ```bash
    # ================================
    # 1. Define PostgreSQL Variables
    # ================================

    PG_VERSION="17"
    PG_DATA_DIR="/var/lib/pgsql/${PG_VERSION}/data"
    PG_CONF="${PG_DATA_DIR}/postgresql.conf"

    # ================================
    # 2. Define PostgreSQL Parameters
    # ================================

    PG_PORT="5432"
    PG_LISTEN_ADDRESSES="*"
    PG_MAX_CONNECTIONS="1000"
    PG_SHARED_BUFFERS="1024MB"
    PG_WAL_BUFFERS="16MB"
    PG_MAX_WAL_SIZE="6GB"
    PG_MIN_WAL_SIZE="512MB"
    PG_CHECKPOINT_COMPLETION_TARGET="0.9"
    PG_STANDARD_CONFORMING_STRINGS="off"
    PG_JIT="off"

    # ================================
    # 3. Verify PostgreSQL Config
    # ================================

    cd "${PG_DATA_DIR}" || exit 1
    cp "${PG_CONF}" "${PG_CONF}.bak.$(date +%Y%m%d_%H%M%S)"

    # ================================
    # 4. Update postgresql.conf
    # ================================

    sed -i -E \
      -e "s|^[[:space:]]*#?[[:space:]]*port[[:space:]]*=.*|port = ${PG_PORT}|" \
      -e "s|^[[:space:]]*#?[[:space:]]*listen_addresses[[:space:]]*=.*|listen_addresses = '${PG_LISTEN_ADDRESSES}'|" \
      -e "s|^[[:space:]]*#?[[:space:]]*max_connections[[:space:]]*=.*|max_connections = ${PG_MAX_CONNECTIONS}|" \
      -e "s|^[[:space:]]*#?[[:space:]]*shared_buffers[[:space:]]*=.*|shared_buffers = ${PG_SHARED_BUFFERS}|" \
      -e "s|^[[:space:]]*#?[[:space:]]*wal_buffers[[:space:]]*=.*|wal_buffers = ${PG_WAL_BUFFERS}|" \
      -e "s|^[[:space:]]*#?[[:space:]]*max_wal_size[[:space:]]*=.*|max_wal_size = ${PG_MAX_WAL_SIZE}|" \
      -e "s|^[[:space:]]*#?[[:space:]]*min_wal_size[[:space:]]*=.*|min_wal_size = ${PG_MIN_WAL_SIZE}|" \
      -e "s|^[[:space:]]*#?[[:space:]]*checkpoint_completion_target[[:space:]]*=.*|checkpoint_completion_target = ${PG_CHECKPOINT_COMPLETION_TARGET}|" \
      -e "s|^[[:space:]]*#?[[:space:]]*standard_conforming_strings[[:space:]]*=.*|standard_conforming_strings = ${PG_STANDARD_CONFORMING_STRINGS}|" \
      -e "s|^[[:space:]]*#?[[:space:]]*jit[[:space:]]*=.*|jit = ${PG_JIT}|" \
      "${PG_CONF}"

    # ================================
    # 5. Verify Updated Parameters
    # ================================

    grep -E \
    '^[[:space:]]*(port|listen_addresses|max_connections|shared_buffers|wal_buffers|max_wal_size|min_wal_size|checkpoint_completion_target|standard_conforming_strings|jit)[[:space:]]*=' \
    "${PG_CONF}"
    cd -
    ```

    Back up the config so you can use it in case of a re-setup.

    ```transcript
    [root@cldr-mngr ~]# cp /var/lib/pgsql/17/data/postgresql.conf ~
    ```

    If you have the file backed up already, copy it *(only applicable in case of resetup)*.

    ```transcript
    [root@cldr-mngr ~]# cp /var/lib/pgsql/17/data/postgresql.conf /var/lib/pgsql/17/data/postgresql.conf_orig
    [root@cldr-mngr ~]# cp ~/postgresql.conf /var/lib/pgsql/17/data/postgresql.conf
    ```

    <Banner type="info">
    Settings vary based on cluster size and resources.
    </Banner>

5. Start the PostgreSQL Server and configure it to start at boot.

    ```transcript
    [root@cldr-mngr ~]# systemctl start postgresql-17.service
    [root@cldr-mngr ~]# systemctl enable postgresql-17.service
    [root@cldr-mngr ~]# systemctl status postgresql-17.service -l
    [root@cldr-mngr ~]# netstat -ltnupa | grep LIST | grep -E '5432|postgres'
    ```

6. Create or verify login

    ```transcript
    [root@cldr-mngr ~]# sudo -u postgres psql
    could not change directory to "/root": Permission denied
    psql (17.13)
    Type "help" for help.

    postgres=# ALTER USER postgres PASSWORD 'postgres';
    ALTER ROLE
    postgres=# \q

    [root@cldr-mngr ~]# psql -h cldr-mngr.cldrsetup.local -d postgres -U postgres
    Password for user postgres:
    psql (17.13)
    Type "help" for help.

    postgres=#\q
    ```

Fix the permissions, switch SSL on in `postgresql.conf`, and restart. First, correct the permissions for the certificates and the private key file:

```transcript
[root@cldr-mngr data]# chmod 644 server.crt root.crt
[root@cldr-mngr data]# chmod 0600 /var/lib/pgsql/17/data/server.key
```

Edit the PostgreSQL configuration file `postgresql.conf` to enable SSL.

```transcript
[root@cldr-mngr data]# cat <<EOF >> /var/lib/pgsql/17/data/postgresql.conf
ssl = on
ssl_ca_file = 'root.crt'
ssl_cert_file = 'server.crt'
ssl_key_file = 'server.key'
EOF
```

Find the location of the private key file, typically in the data directory.

```transcript
[root@cldr-mngr data]# ls -l /var/lib/pgsql/17/data/server.key
```

Restart the PostgreSQL database service to pick up the SSL-related configuration changes, then verify that login works with SSL.

```transcript
[root@cldr-mngr data]# systemctl restart postgresql-17.service
[root@cldr-mngr data]# systemctl status postgresql-17.service -l

[root@jump ~]# ansible all -m shell -a "mkdir -p /root/.postgresql/ && chmod -R 755 /root/.postgresql/"
[root@jump ~]# ansible all -m copy -a "src=root.crt dest=/root/.postgresql/root.crt"
```

## 4. Create the databases and service accounts

Create databases and service accounts for components that require databases. Following components requires databases:

- [https://docs.cloudera.com/cdp-private-cloud-base/7.3.2/cdp-private-cloud-base-installation/topics/cdpdc-required-databases.html](https://docs.cloudera.com/cdp-private-cloud-base/7.3.2/cdp-private-cloud-base-installation/topics/cdpdc-required-databases.html)
- [https://docs.cloudera.com/cdp-private-cloud-base/7.3.2/cdp-private-cloud-base-installation/topics/cdpdc-configuring-starting-postgresql-server.html](https://docs.cloudera.com/cdp-private-cloud-base/7.3.2/cdp-private-cloud-base-installation/topics/cdpdc-configuring-starting-postgresql-server.html)

<Banner type="warning">
The databases must be configured to support the PostgreSQL UTF8 character set encoding.
</Banner>

<Banner type="warning">
Record the values you enter for database names, usernames, and passwords. The Cloudera Manager installation wizard requires this information to correctly connect to these databases.
</Banner>

Create the Cloudera Manager databases and users.

```transcript
[root@cldr-mngr data]# sudo -u postgres psql

CREATE ROLE scm LOGIN PASSWORD 'scm';
CREATE DATABASE scm OWNER scm ENCODING 'UTF8';
GRANT ALL PRIVILEGES ON DATABASE scm TO scm;

CREATE ROLE rman LOGIN PASSWORD 'rman';
CREATE DATABASE rman OWNER rman ENCODING 'UTF8';
GRANT ALL PRIVILEGES ON DATABASE rman TO rman;

CREATE ROLE hue LOGIN PASSWORD 'hue';
CREATE DATABASE hue OWNER hue ENCODING 'UTF8';
GRANT ALL PRIVILEGES ON DATABASE hue TO hue;

CREATE ROLE hive LOGIN PASSWORD 'hive';
CREATE DATABASE hive OWNER hive ENCODING 'UTF8';
GRANT ALL PRIVILEGES ON DATABASE hive TO hive;

CREATE ROLE oozie LOGIN PASSWORD 'oozie';
CREATE DATABASE oozie OWNER oozie ENCODING 'UTF8';
GRANT ALL PRIVILEGES ON DATABASE oozie TO oozie;

CREATE ROLE rangeradmin LOGIN PASSWORD 'rangeradmin';
CREATE DATABASE ranger OWNER rangeradmin ENCODING 'UTF8';
GRANT ALL PRIVILEGES ON DATABASE ranger TO rangeradmin;

/*For Ranger KMS, use rangerkms rather than rangeradmin user.*/
CREATE ROLE rangerkms LOGIN PASSWORD 'rangerkms';
CREATE DATABASE rangerkms OWNER rangerkms ENCODING 'UTF8';
GRANT ALL PRIVILEGES ON DATABASE rangerkms TO rangerkms;

CREATE ROLE schemaregistry LOGIN PASSWORD 'schemaregistry';
CREATE DATABASE schemaregistry OWNER schemaregistry ENCODING 'UTF8';
GRANT ALL PRIVILEGES ON DATABASE schemaregistry TO schemaregistry;

CREATE ROLE yqm LOGIN PASSWORD 'yqm';
CREATE DATABASE yqm OWNER yqm ENCODING 'UTF8';
GRANT ALL PRIVILEGES ON DATABASE yqm TO yqm;

CREATE ROLE nifiregistry LOGIN PASSWORD 'nifiregistry';
CREATE DATABASE nifiregistry OWNER nifiregistry ENCODING 'UTF8';
GRANT ALL PRIVILEGES ON DATABASE nifiregistry TO nifiregistry;

CREATE ROLE impala LOGIN PASSWORD 'impala';
CREATE DATABASE impala OWNER impala ENCODING 'UTF8';
GRANT ALL PRIVILEGES ON DATABASE impala TO impala;

CREATE ROLE dataviz LOGIN PASSWORD 'dataviz';
CREATE DATABASE dataviz OWNER dataviz ENCODING 'UTF8';
GRANT ALL PRIVILEGES ON DATABASE dataviz TO dataviz;

CREATE ROLE knox LOGIN PASSWORD 'knox';
CREATE DATABASE knox OWNER knox ENCODING 'UTF8';
GRANT ALL PRIVILEGES ON DATABASE knox TO knox;

/*For the SMM metadata store, create a database called smm with the password smm:*/
CREATE ROLE smm LOGIN PASSWORD 'smm';
CREATE DATABASE smm OWNER smm ENCODING 'UTF8';
GRANT ALL PRIVILEGES ON DATABASE smm TO smm;

CREATE ROLE das LOGIN PASSWORD 'das';
CREATE DATABASE das OWNER das ENCODING 'UTF8';
GRANT ALL PRIVILEGES ON DATABASE das TO das;

ALTER DATABASE hive SET standard_conforming_strings=off;
ALTER DATABASE oozie SET standard_conforming_strings=off;
SELECT 1;
SHOW ssl;
\q
```

<Banner type="info">
If you plan to use Apache Ranger, please visit Configuring a PostgreSQL Database for Ranger or Ranger KMS for instructions on creating and configuring the Ranger database. **included above- install JDBC driver, create DB for ranger etc.**
</Banner>

<Banner type="info">
If you plan to use Schema Registry or Streams Messaging Manager, please visit Configuring the Database for Streaming Components for instructions on configuring the database. included above- create smm and registry db etc.
</Banner>

<Banner type="important">
**Every password above is the role name.** The guide's lab build uses `scm/scm`, `hive/hive`, `ranger/rangeradmin` and so on throughout. Substitute real credentials before running any of this outside a disposable lab, and record them - the Cloudera Manager installation wizard asks for them later.
</Banner>
