<Banner type="info">
All four procedures on this page are optional. Without them each service keeps the authentication it already has: Ranger and Atlas fall back to the local OS users on the hosts running them, Hue to its own internal user database, and Hive to Kerberos ticket authentication instead of LDAP username and password.
</Banner>

## 1. Configure Ranger authentication for LDAP

Follow steps below to configure Ranger for LDAP authentication.

1. In Cloudera Manager, select **Ranger**, then click the **Configuration** tab.

2. To display the authentication settings, type `authentication` in the Search box. Scroll down to see all of the LDAP settings.

3. Select LDAP for "Admin Authentication Method".

    ![Ranger Configuration tab searched for authentication, with Admin Authentication Method set to LDAP among the UNIX, LDAP, ACTIVE_DIRECTORY, PAM and NONE options, and Admin UNIX Auth Remote Login checked](/images/cdp-7-3-2/on-premises/base/ldap-auth/ranger-admin-authentication-method.png)

4. Configure the following settings for LDAP authentication as shown below, the details depends on your configuration, based on existing LDAP/AD setup:

    **User LDAP Integration**

    | Component | Value |
    |:--|:--|
    | Admin LDAP/AD Auth URL | ldap://ipaserver.cldrsetup.local:389/ (Give LDAP or AD Server LDAP ADDR) |
    | Admin LDAP/AD Auth Bind User/ Bind DN | uid=admin,cn=users,cn=accounts,dc=cldrsetup,dc=local |
    | Admin LDAP/AD Auth Bind User Password | `<ldap_bind_password>` (password for KDC admin, configured earlier) |
    | Admin LDAP/AD Auth User DN Pattern | uid=admin,cn=users,cn=accounts,dc=cldrsetup,dc=local |
    | Admin LDAP/AD Auth User Search Filter | For AD: `(&(objectClass=user)(sAMAccountName={0}))` — For LDAP: `(&(objectClass=person)(uid={0}))` |
    | Admin LDAP/AD Auth Group Search Base | cn=groups,cn=accounts,dc=cldrsetup,dc=local |
    | Admin LDAP/AD Auth Group Search Filter | For AD: `(&(objectClass=group)(member={0}))` — For LDAP: `(&(objectClass=posixGroup)(memberUid={0}))` |
    | Admin LDAP/AD Auth Group Role Attribute | cn |
    | Admin LDAP/AD Auth Base DN | dc=cldrsetup,dc=local |
    | Admin LDAP/AD Auth Referral | follow |
    | Admin AD Auth Domain Name (For AD Setup) | cldrsetup.local |

    Search under Configuration for `ranger.ldap`.

    ![Ranger Configuration filtered on ranger.ldap, showing Admin LDAP Auth URL, Bind User, Bind User Password, User DN Pattern, User Search Filter, Group Search Base, Group Search Filter, Group Role Attribute, Base DN and Referral set to follow](/images/cdp-7-3-2/on-premises/base/ldap-auth/ranger-ldap-config.png)

    Additional parameters required for AD Based integration: search under Configuration for `ranger.ldap.ad`.

    ![Ranger Configuration filtered on ranger.ldap.ad, showing the seven Admin AD Auth properties - URL, Bind DN, Bind Password, Domain Name, Base DN, Referral set to follow, and User Search Filter - with every text field left empty in this LDAP-based setup](/images/cdp-7-3-2/on-premises/base/ldap-auth/ranger-ldap-ad-config.png)

5. Edit Usersync configuration. Example values set are shown in the screenshots below:

    ![Ranger Usersync configuration part 1 - Source for Syncing User and Groups set to org.apache.ranger.ldapusersync.process.LdapUserGroupBuilder, Usersync LDAP/AD URL, Bind User, Bind User Password, Incremental Sync checked, Enable STARTTLS unchecked and User Search Base](/images/cdp-7-3-2/on-premises/base/ldap-auth/ranger-usersync-config-1.png)

    ![Ranger Usersync configuration part 2 - User Search Scope sub, User Object Class, User Search Filter, User Name Attribute, Referral follow, Username Case Conversion and Groupname Case Conversion](/images/cdp-7-3-2/on-premises/base/ldap-auth/ranger-usersync-config-2.png)

    ![Ranger Usersync configuration part 3 - Enable User Search checked, Group Search Base, Group Object Class, Group Name Attribute, Group Member Attribute, Group Hierarchy Levels 0 and Ldap Group Names](/images/cdp-7-3-2/on-premises/base/ldap-auth/ranger-usersync-config-3.png)

    **UserSync LDAP/AD Integration**

    Rows tagged For AD / For LDAP take a different value depending on the directory type; every other row applies to both.

    | Component | Value |
    |:--|:--|
    | Source for Syncing User and Groups | org.apache.ranger.ldapusersync.process.LdapUserGroupBuilder |
    | Ranger Usersync Unix Backend | nss |
    | Usersync LDAP/AD URL | ldap://ipaserver.cldrsetup.local:389/ |
    | Usersync Bind User | For AD: Administrator@cldrsetup.local — For LDAP: uid=admin,cn=users,cn=accounts,dc=cldrsetup,dc=local |
    | Usersync Bind User Password | `<ldap_bind_password>` (password for KDC admin, configured earlier) |
    | Usersync User Search Base | For AD: OU=cloudera,DC=cldrsetup,DC=local — For LDAP: cn=users,cn=accounts,dc=cldrsetup,dc=local |
    | Usersync User Search Scope | sub |
    | Usersync User Object Class | For AD: user — For LDAP: person |
    | Usersync User Search Filter | For AD: (sAMAccountName=*) — For LDAP: uid=* |
    | Usersync User Name Attribute | For AD: sAMAccountName — For LDAP: uid |
    | Usersync Referral | follow |
    | Usersync Username Case Conversion | none |
    | Usersync Groupname Case Conversion | none |
    | Usersync Enable User Search | Ranger Usersync Default Group |
    | Usersync Group Search Base | For AD: OU=cloudera,DC=cldrsetup,DC=local — For LDAP: cn=groups,cn=accounts,dc=cldrsetup,dc=local<br />*An OU would need to be mentioned to configure ldap if you are using AD based setup* |
    | Usersync Group Search Filter | For AD: `(&(objectClass=group)(member={0}))` — For LDAP: `(&(objectClass=posixGroup)(memberUid={0}))` |
    | Usersync Group Search Scope | sub |
    | Usersync Group Object Class | For AD: group — For LDAP: ipausergroup |
    | Usersync Group Name Attribute | cn |
    | Usersync Group Member Attribute | For AD: `(member={1})` — For LDAP: member |

6. Click on save changes.

7. Restart Ranger service.

8. Login to Ranger Admin WebUI with ldap authentication.

For more details: [https://docs.cloudera.com/cdp-private-cloud-base/7.3.2/security-ranger-authentication-unix-ldap-ad/topics/security-ranger-authentication-ldap-settings.html](https://docs.cloudera.com/cdp-private-cloud-base/7.3.2/security-ranger-authentication-unix-ldap-ad/topics/security-ranger-authentication-ldap-settings.html).

## 2. Configure Hue for LDAP Authentication

Configuring Hue for Lightweight Directory Access Protocol (LDAP) enables you to import users and groups from a directory service, synchronize group membership manually or automatically at login, and authenticate with an LDAP server. Hue supports Microsoft Active Directory (AD) and open standard LDAP such as OpenLDAP and Forgerock OpenDJ Directory Services.

1. Login to Cloudera Manager. Go to **Cluster > Hue > Configuration**.

2. Change value for Authentication Backend:

    ```text
    desktop.auth.backend.LdapBeckend,desktop.auth.backend.AllowFirstUserDjangoBackend
    ```

    ![Hue Authentication Backend property, backend / auth_backend, set service-wide to desktop.auth.backend.LdapBackend,desktop.auth.backend.AllowFirstUserDjangoBackend](/images/cdp-7-3-2/on-premises/base/ldap-auth/hue-authentication-backend.png)

    The prose spells the first class `LdapBeckend` while the screenshot shows `LdapBackend`; the prose is transcribed as printed, and the screenshot spelling is the one Hue actually accepts.

3. Edit value for LDAP configuration. Example values set are shown in the screenshots below:

    ![Hue LDAP configuration part 1 - LDAP URL, LDAP Server CA Certificate, Enable LDAP TLS checked, Active Directory Domain, LDAP Username Pattern, Use Search Bind Authentication checked, Create LDAP users on login checked and LDAP Search Base](/images/cdp-7-3-2/on-premises/base/ldap-auth/hue-ldap-config-1.png)

    ![Hue LDAP configuration part 2 - LDAP Bind User Distinguished Name, Bind Password, Username and Group Name for Test LDAP Configuration, LDAP User Filter, Username Attribute, Group Filter, Group Name Attribute and Group Membership Attribute](/images/cdp-7-3-2/on-premises/base/ldap-auth/hue-ldap-config-2.png)

    **Table: LDAP Integration**

    | Component | Value |
    |:--|:--|
    | LDAP URL | ldap://ipaserver.cldrsetup.local:389/ |
    | LDAP Server CA Certificate (Optional) | Leave it blank |
    | Enable LDAP TLS (Hue) | True (Checked) |
    | LDAP Search Base | cn=users,cn=accounts,dc=cldrsetup,dc=local |
    | LDAP Bind User Distinguished Name | uid=admin,cn=users,cn=accounts,dc=cldrsetup,dc=local |
    | LDAP Bind Password | `<ldap_bind_password>` (password for KDC admin, configured earlier) |
    | LDAP Username for Test LDAP Config | admin |
    | LDAP Group Name for Test LDAP Config | Leave it blank |
    | LDAP User filter | Leave it blank |
    | LDAP Group filter | Leave it blank |
    | LDAP Group Name Attribute | cn |
    | LDAP Group Membership Attribute | member |

4. Click on save changes.

5. Restart HUE service.

6. Click on Actions next to Hue. Click on Test LDAP Configuration.

    ![Hue service page with the Actions menu open, showing Start, Stop, Restart, Rolling Restart, Add Role Instances, Rename, Delete, Enter Maintenance Mode, Dump Database, Synchronize database, Load Database, Create the Hue User Directory and Test LDAP Configuration](/images/cdp-7-3-2/on-premises/base/ldap-auth/hue-actions-test-ldap.png)

7. Click on Test LDAP Configuration.

    ![Test LDAP Configuration confirmation dialog for the Hue service, explaining that the command tests Hue's LDAP configuration and should be run whenever it is modified, with Cancel and Test LDAP Configuration buttons](/images/cdp-7-3-2/on-premises/base/ldap-auth/hue-test-ldap-dialog.png)

8. Click on Finish.

    ![Test LDAP Configuration command finished for the Hue context, reporting that Hue's LDAP configuration is valid, 1 of 1 steps completed, with the Testing the Hue LDAP configuration step green](/images/cdp-7-3-2/on-premises/base/ldap-auth/hue-test-ldap-finished.png)

For more details: [https://docs.cloudera.com/cdp-private-cloud-base/7.3.2/securing-hue/topics/hue-authenticate-users-with-ldap.html](https://docs.cloudera.com/cdp-private-cloud-base/7.3.2/securing-hue/topics/hue-authenticate-users-with-ldap.html).

## 3. Configure Atlas for LDAP authentication

Follow steps below to configure Atlas authentication for LDAP. If LDAP is not integrated for Atlas, we need to use local OS users present on the node where Atlas server is installed i.e. `base-master`.

1. Login to Cloudera Manager WebUI. Go to **Cluster > Atlas > Configuration**.

2. Edit LDAP configuration. Sample configuration is shown in the screenshots below:

    ![Atlas LDAP configuration part 1 - Enable LDAP Authentication checked, LDAP Server URL, User DN Pattern, Group-Search Base, Group-Search Filter, Group-Role Attribute, LDAP DN, Bind DN Username, Bind DN Password, Referral set to follow and User Search Filter](/images/cdp-7-3-2/on-premises/base/ldap-auth/atlas-ldap-config-1.png)

    ![Atlas LDAP configuration part 2 - AD Referral set to follow, AD User Search Filter, AD User Default Role ROLE_USER and LDAP Authentication Type set to ldap out of none, ldap and ad](/images/cdp-7-3-2/on-premises/base/ldap-auth/atlas-ldap-config-2.png)

    **Atlas LDAP Integration**

    | Component | Value |
    |:--|:--|
    | Enable LDAP Authentication (Atlas) | True (Checked) |
    | LDAP Server URL | ldap://ipaserver.cldrsetup.local:389/ |
    | LDAP Group Search filter | `(&(member={1})(objectClass=posixgroup))` |
    | LDAP Group Search Base | cn=groups,cn=accounts,dc=cldrsetup,dc=local |
    | LDAP Group-Role Attribute | cn |
    | LDAP DN | dc=cldrsetup,dc=local |
    | LDAP Bind DN Username | uid=admin,cn=users,cn=accounts,dc=cldrsetup,dc=local |
    | LDAP Bind DN Password | `<ldap_bind_password>` (password for KDC admin, configured earlier) |
    | LDAP Referral | follow |
    | LDAP User filter | `(&(uid={0})(objectClass=person))` |
    | LDAP Authentication Type | LDAP |
    | AD Referral (Only for AD Setup) | follow |
    | AD User Search Filter (Only for AD Setup) | `(sAMAccountName={0})` |
    | AD User Default Role (Only for AD Setup) | ROLE_USER |

3. Click on save changes.

4. Restart Atlas service.

For more details: [https://docs.cloudera.com/cdp-private-cloud-base/7.3.2/atlas-securing/topics/atlas-configure-ldap-authentication.html](https://docs.cloudera.com/cdp-private-cloud-base/7.3.2/atlas-securing/topics/atlas-configure-ldap-authentication.html).
